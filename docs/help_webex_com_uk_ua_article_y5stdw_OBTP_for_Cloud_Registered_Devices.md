## ОБТП для пристроїв, зареєстрованих у хмарі
### Як OBTP працює з пристроями, зареєстрованими в хмарі
![](https://cisco-api.ingeniuxondemand.com/DITA/content/en/us/td/i/400001-500000/430001-440000/438001-439000/438683.jpg)**_OBTP для пристроїв, зареєстрованих у хмарі, з конектором календаря на основі Expressway_**
  1. Ви можете запланувати нараду, використовуючи ключове слово або відеоадресу, і запросити кінцеву точку відео, зареєстровану в хмарі, за календарем ресурсів кімнати.
  2. Якщо кінцева точка на той момент доступна, Microsoft Exchange автоматично приймає запрошення від свого імені.
  3. Сповіщення EWS від Microsoft Exchange сповіщають з'єднувач календаря про те, що нараду заплановано.
  4. Для нарад Webex служба гібридного календаря отримує відомості про приєднання з хмари Webex і оновлює запрошення на нараду.
  5. Безпосередньо перед часом зустрічі пристрої, зареєстровані в хмарі, отримують інформацію про OBTP з хмари.

## ОБТП для пристроїв, зареєстрованих у приміщеннях
### Як працює ОБТП з пристроями, зареєстрованими в приміщеннях 
![](https://cisco-api.ingeniuxondemand.com/DITA/content/en/us/td/i/500001-600000/500001-510000/502001-503000/502682.jpg)**_OBTP для пристроїв, зареєстрованих у приміщеннях, за допомогою з'єднувача календаря на основі швидкісної автомагістралі_**
  1. Користувач планує нараду, використовуючи ключове слово або відеоадресу, і запрошує кінцеву точку відео, зареєстровану в приміщенні, за календарем ресурсів кімнати.
  2. Якщо кінцева точка на той момент доступна, зазвичай Microsoft Exchange автоматично приймає запрошення від свого імені.
  3. Сповіщення EWS від Exchange сповіщають з'єднувач календаря та Cisco TMSXE про те, що нараду призначено.
  4. Для зустрічей Cisco Webex служба гібридного календаря отримує дані про приєднання з хмари Cisco Webex і оновлює запрошення на нараду.
  5. З'єднувач календаря заповнює поле опису всіма доступними відомостями про об'єднання та встановлює значення атрибута **користувача "TMS:ExternalConferenceData"** для SIP URI наради.
  6. Сповіщення EWS від Exchange сповіщає Cisco TMSXE про оновлення наради.
  7. Cisco TMSXE оновлює зустріч у Cisco TMS до зовнішнього хостингу та встановлює рядок набору OBTP. 
  8. Cisco TMS надсилає інформацію OBTP для майбутніх зустрічей до кінцевих точок.


### Налаштування ОБТП для пристроїв, зареєстрованих у приміщеннях
Для кінцевих точок, зареєстрованих локально, OBTP працює зі службою гібридних календарів і плагіном Productivity Tools для запрошень на нараду:
  * Служба гібридного календаря (ключові слова планування або підтримувана відеоадреса) заповнює атрибут користувача "TMS:ExternalConferenceData" за допомогою SIP URI для TMS, щоб встановити рядок набору OBTP.
  * Плагін Productivity Tools заповнює атрибут "UCCapabilities" атрибутом SIP URI для TMS, щоб встановити рядок набору OBTP.

  
| 1  |  Налаштуйте Cisco TMS 15.0 та Cisco TMSXE 5.0 або вище з інтеграцією Microsoft Exchange. Перегляньте посібник із гібридної конфігурації переговорних кімнат для спільної [роботи Cisco (CMR) (TMS 15.0 - WebEx Meeting Center WBS30)](http://www.cisco.com/c/en/us/support/conferencing/collaboration-meeting-rooms-cmr/products-installation-and-configuration-guides-list.html).   |  
| --- | --- |  
| 2  |  Щоб зробити конференц-зали доступними для планування в Microsoft Outlook/Exchange, настройте їх у XE так, ніби ви використовуєте локальні конференції. Щоб настроїти кімнати в службі Exchange, скористайтеся [розширенням Cisco TelePresence Management Suite для посібника з](http://www.cisco.com/c/en/us/support/conferencing/telepresence-management-suite-extensions/products-maintenance-guides-list.html)адміністрування Microsoft Exchange.  |  
| 3  |  Отримати ліцензії на TMS і TMSXE. Ліцензування TMS і XE - це те ж саме, що і при використанні локальних ресурсів. Потрібна достатня кількість ліцензій, щоб покрити кількість кінцевих точок, які будуть використовувати OBTP. Ліцензія TMS потрібна для управління кінцевою точкою та натискання кнопки швидкого набору на тачпаді під час запланованої конференції. Ліцензія TMS-XE необхідна для того, щоб кінцева точка була запланована в Exchange.  |  
| 4  |  Якщо ви плануєте розгорнути гібридне середовище Exchange зі службою Office 365, увімкніть функцію TNEF для віддалених доменів у службі Exchange Online. Вимкнення TNEF призводить до того, що служба Exchange Online видаляє атрибути TMS:ExternalConferenceData та UCCapabilities, порушуючи OBTP для кінцевих точок, зареєстрованих уніфікованою CM.  Більш детальну інформацію про TNEF дивіться <https://docs.microsoft.com/en-us/exchange/mail-flow/content-conversion/tnef-conversion>.  |  
Якщо у вас є локальні конференції, ви можете додати OBTP до Cisco Webex Meetings і запускати обидві одночасно. Ми підтримуємо тільки функціональність OBTP; автоматичне підключення недоступне.
### Усунення несправностей із кнопкою Приєднатися
#### Кнопка "Без приєднання" на пристроях із локальною реєстрацією 
У середовищі гібридного обміну кнопка «Приєднатися» не відображається на жодному пристрої, зареєстрованому в приміщеннях.
У гібридних середовищах Exchange вимкнення TNEF для віддалених доменів призводить до видалення Exchange Online TMS:ExternalConferenceData та атрибути користувача UCCapabilities для зустрічі. Це порушує OBTP для уніфікованих кінцевих точок, зареєстрованих CM. Без цих атрибутів Cisco TMSXE не може оновити зустріч в Cisco TMS, а Cisco TMS не може встановити рядок набору OBTP для зустрічі.
Щоб виправити цю проблему, перевірте, чи дозволено TNEF для віддалених доменів. Інструкції див. на [Exchange Server: Варіанти перетворення TNEF](https://docs.microsoft.com/en-us/exchange/mail-flow/content-conversion/tnef-conversion).
#### Кнопка "Без приєднання" на певному пристрої
Пристрій не відображає кнопку приєднання, коли зустрічі ось-ось розпочнуться.
Пристрій не приймає запрошення на зустрічі автоматично.
Перевірте календар ресурсів для пристрою та перевірте, чи прийняв він запрошення на зустріч. Якщо ні, настройте поштову скриньку ресурсів пристрою на автоматичне прийняття запрошень на нараду.
