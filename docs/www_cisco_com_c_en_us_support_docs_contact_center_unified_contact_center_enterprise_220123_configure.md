## Introduction
This document describes how to secure Real-time Transport Protocol (SRTP) Traffic in Contact Center Enterprise (CCE) comprehensive call flow.
## Prerequisites
Certificates generation and import are out of the scope of this document, so certificates for Cisco Unified Communication Manager (CUCM), Customer Voice Portal (CVP) Call Server, Cisco Virtual Voice Browser (CVVB), and Cisco Unified Border Element (CUBE) have to be created and imported to the respective components. If you use self-signed certificates, certificate exchange has to be done among different components.
### Requirements
Cisco recommends that you have knowledge of these topics:
  * CCE
  * CVP
  * CUBE
  * CUCM
  * CVVB


### Components Used
The information in this document is based on Package Contact Center Enterprise (PCCE), CVP, CVVB, and CUCM version 12.6, but it is also applicable to the previous versions.
The information in this document was created from the devices in a specific lab environment. All of the devices used in this document started with a cleared (default) configuration. If your network is live, ensure that you understand the potential impact of any command.
## Configure
**Note** : In the contact center comprehensive call flow, In order to enable secure RTP, secure SIP signals must be enabled. Therefore, configurations in this document enable both secure SIP and SRTP.
The next diagram shows the components engaged in SIP signals and RTP in the contact center comprehensive call flow. When a voice call comes to the system, it first comes via the ingress gateway or CUBE, so start the configurations on CUBE. Next, configure CVP, CVVB, and CUCM.  
  

[![Inbound SIP and RTP Call Flow](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-00.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-00.png "Inbound SIP and RTP Call Flow")
### Task 1: CUBE Secure Configuration
In this task, you configure CUBE to secure SIP protocol messages and RTP.
Required configurations:
  * Configure a Default Trustpoint for the SIP UA
  * Modify the Dial-peers to use TLS and SRTP


Steps:
  1. Open an SSH session to CUBE.


  1. Run these commands to have the SIP stack use the CA certificate of the CUBE. CUBE establishes SIP TLS connection from/to CUCM (198.18.133.3) and CVP (198.18.133.13):


**`Conf t Sip-ua Transport tcp tls v1.2 crypto signaling remote-addr 198.18.133.3 255.255.255.255 trustpoint ms-ca-name crypto signaling remote-addr 198.18.133.13 255.255.255.255 trustpoint ms-ca-name exit`**
[![CUBE SSH Console](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-01.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-01.png "CUBE SSH Console")
  1. Run these commands to enable TLS on the outgoing dial peer to CVP. In this example, dial-peer tag 6000 is used to route calls to CVP:


**`Conf t dial-peer voice 6000 voip session target ipv4:198.18.133.13:5061 session transport tcp tls srtp exit  `**
[![CUBE SSH Console](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-02.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-02.png "CUBE SSH Console")
### Task 2: CVP Secure Configuration
In this task, configure the CVP call server to secure the SIP protocol messages (SIP TLS).
Steps:
  1. Login to the **`UCCE Web Administration`**.
  2. Navigate to **`Call Settings > Route Settings > SIP Server Group`**.  
  



[![SIP Server Group Configuration on CCE Admin Portal](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-03.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-03.png "SIP Server Group Configuration on CCE Admin Portal")
Based on your configurations, you have SIP Server Groups configured for CUCM, CVVB, and CUBE. You need to set secure SIP ports to 5061 for all of them. In this example, these SIP server groups are used:
  * **`cucm1.dcloud.cisco.com`**for CUCM
  * **`vvb1.dcloud.cisco.com`**for CVVB
  * **`cube1.dcloud.cisco.com`** for CUBE


  1. Click **`cucm1.dcloud.cisco.com`**,and then in the**`Members`** tab that shows the details of SIP Server Group Configurations. Set **`SecurePort`**to**`5061`**and click**`Save`**.  
  



[![Setting secure SIP Port for CUCM Server Group](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-04.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-04.png "Setting secure SIP Port for CUCM Server Group")
  1. Click **`vvb1.dcloud.cisco.com`**and then in the**`Members`** tab, set the**`SecurePort`** to **`5061`** and click **`Save`**.  
  



[![Setting secure SIP Port for VVB Server Group](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-05.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-05.png "Setting secure SIP Port for VVB Server Group")
### Task 3: CVVB Secure Configuration
In this task, configure CVVB to secure the SIP protocol messages (SIP TLS) and SRTP.
Steps:
  1. Open the **`Cisco VVB Admin`** page.
  2. Navigate to **`System > System Parameters`**.  
  



[![VVB System Parameters](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-06.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-06.png "VVB System Parameters")
  1. On the **`Security Parameters`**section, choose**`Enable`**for**`TLS (SIP) `**. Keep the**`Supported TLS(SIP) version as TLSv1.2`** and choose **`Enable`**for**`SRTP`**.  
  



[![VVB Security Parameters](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-07.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-07.png "VVB Security Parameters")
  1. Click **`Update`**. Click **`Ok`**when prompted to restart the CVVB engine.  
  



[![Update Security Parameters](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-08.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-08.png "Update Security Parameters")
  1. These changes require a restart of the Cisco VVB engine. In order to restart the VVB engine, navigate to the **`Cisco VVB Serviceability`**, then click**`Go`**.  
  



[![Cisco VVB Serviceability](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-09.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-09.png "Cisco VVB Serviceability")
  1. Navigate to **`Tools > Control Center – Network Services`**.  
  



[![Control Center - Network Services](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-10.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-10.png "Control Center - Network Services")
  1. Choose **`Engine`**and click**`Restart`**.  
  



[![Restarting CVVB Engine Services](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-11.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-11.png "Restarting CVVB Engine Services")
### Task 4: CUCM Secure Configuration
In order to secure SIP messages and RTP on CUCM, perform these configurations:
  * Set CUCM Security Mode to Mixed Mode
  * Configure SIP Trunk Security Profiles for CUBE and CVP
  * Associate SIP Trunk Security Profiles to Respective SIP Trunks and enable SRTP
  * Secure Agents’ device Communication with CUCM


#### **Set CUCM Security Mode to Mixed Mode**
CUCM supports two security modes:
  * Non-secure mode (default mode)
  * Mixed mode (secure mode)


Steps:
  1. Log in to the CUCM administration interface.  
  



[![CUCM Administration Interface](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-12.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-12.png "CUCM Administration Interface")  
  

  1. When you log in to the CUCM, you can navigate to **`System > Enterprise Parameters`**.  
  



[![CUCM Enterprise Parameters](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-13.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-13.png "CUCM Enterprise Parameters")
  1. Under the **`Security Parameters`**section, check if the**`Cluster Security Mode`**is set to**`0`**.  
  



[![CUCM Security Parameters](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-14.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-14.png "CUCM Security Parameters")
  1. If Cluster Security Mode is set to 0, this means cluster security mode is set to non-secure. You need to enable the mixed Mode from CLI.
  2. Open an SSH session to the CUCM.
  3. Upon successful login to CUCM via SSH, run this command:


**utils ctl set-cluster mixed-mode**
  1. Type **`y`**and click**`Enter`**when prompted. This command sets cluster security mode to mixed mode.  
  



[![CUCM SSH Console](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-15.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-15.png "CUCM SSH Console")
  1. For the changes to take effect, restart the **`Cisco CallManager`**and the**`Cisco CTIManager`**services.
  2. In order to restart the services, navigate and log in to**`Cisco Unified Serviceability`**.  
  



[![Cisco Unified Serviceability](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-16.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-16.png "Cisco Unified Serviceability")
  1. After successful login, navigate to **`Tools > Control Center – Feature Services`**.  
  



[![Control Center - Feature Services](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-17.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-17.png "Control Center - Feature Services")  
  

  1. Choose the server and then click **`Go`**.  
  



[![Select Server](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-18.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-18.png "Select Server")
  1. Underneath CM services, choose the **`Cisco CallManager`**, then click**`Restart`** button at the top of the page.  
  



[![Restarting Cisco CallManager Service](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-19.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-19.png "Restarting Cisco CallManager Service")
  1. Confirm the pop-up message and click **`OK`**. Wait for the service to successfully restart.

  2. Navigate to **`Tools > Service Activation`**.

## Verify
In order to validate RTP is properly secured, perform these steps:
  1. Make a test call to the contact center, and listen to IVR prompt.
  2. At the same time, open the SSH session to vCUBE, and run this command:  
**`show call active voice brief`**  
  



[![show call active voice brief Command Output on CUBE SSH Console](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-52.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-52.png "show call active voice brief Command Output on CUBE SSH Console")
**Tip** : Check if the SRTP is **`on`**between CUBE and VVB (198.18.133.143). If yes, this confirms RTP traffic between CUBE and VVB is secure.
  1. Make an agent available to answer the call.  
.[![Make Agent Ready on Finesse Agent Desktop](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-53.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-53.png "Make Agent Ready on Finesse Agent Desktop")
  2. The agent gets reserved and the call is routed to the agent. Answer the call.
  3. The call gets connected to the agent. Go back to the vCUBE SSH session, and run this command:  
**`show call active voice brief`**  
  



[![show call active voice brief Command Output on CUBE SSH Console](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-54.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-54.png "show call active voice brief Command Output on CUBE SSH Console")
**Tip** : Check if the SRTP is **`on`**between CUBE and the agents' phones (198.18.133.75). If yes, this confirms RTP traffic between CUBE and Agent is secure.
  1. Also, once the call is connected, a security lock is displayed on the agent device. This also confirms the RTP traffic is secure.  
  



[![Secure Lock Appears, Confirm SRTP is Established](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-55.png)](https://www.cisco.com/c/dam/en/us/support/docs/contact-center/unified-contact-center-enterprise/220123-configure-secure-rtp-in-contact-center-e-55.png "Secure Lock Appears, Confirm SRTP is Established")
To validate that the SIP signals are properly secured, refer to [Configure Secure SIP Signaling](https://www.cisco.com/c/en/us/support/docs/contact-center/unified-contact-center-enterprise/218434-configure-secure-sip-signaling-in-contac.html "Configure Secure SIP Signaling in Contact Center Enterprise") article.
