## Background Information
SDA North-South Traffic Flow refers to the concept where an endpoint that exists within the SDA Fabric and wants to communicate with an endpoint or server, that is not within the SDA Fabric.
  * First, the endpoint resolves ARP for its default gateway, which is the Fabric Edge node
  * Then the endpoint send the IP packet towards the default gateway, which is the Anycast Gateway on the Fabric Edge node.
  * The Fabric Edge node uses Cisco Express Forwarding (CEF) to send the packet out, which Locator ID Separator Protocol (LISP) drives CEF.
  * The Fabric Edge node has a map-cache entry for 0.0.0.0/0, default route and the action is to encapsulate all packets towards the Proxy Egress Tunnel Router (PETR), or the SDA Fabric Border Node(s).
  * The Fabric Edge node encapsulates the original IP packet in VXLAN and forward the packet towards the SDA Fabric Border Node(s).
  * The Border Node decapsulates the packet and execute an IP lookup against the original packet destination IP address, and forward the packet towards the appropriate next-hop, which more than likely is an upstream Fusion Router that is not part of the SDA Fabric.
  * Next, for return traffic headed back towards the endpoint within the SDA Fabric, the packet is received by the Fusion Router and also executes an IP lookup against the destination IP address and forward it towards the appropriate next-hop, which is be a Border node.
  * The Fabric Border node consults CEF which is derived from LISP to determine which Fabric Edge node is associated with the endpoint and encapsulate the original packet in VXLAN and send it out.
  * The Fabric Edge decapsulates the packet and forward the original packet towards the endpoint.
