### Defect Information  
| Defect ID  | Headline  |  
| --- | --- |  
| [CSCvs64158](https://bst.cloudapps.cisco.com/bugsearch/bug/CSCvs64158)  | Call Home Certificate Expires Feb 7 2020 for VOS Products  |  
### Problem Description
The Call Home Certificate that is included by default in many of the Cisco Unified Collaboration products expires on 2020-02-07.
### Background
Cisco customers reported that they had received alerts about a certificate that was about to expire. Upon investigation, Cisco discovered that the Call Home Certificate included by default in the ISO image file has not been updated and expires in February 2020.
### Problem Symptom
In the CiscoSyslog file, you may see a message similar to this one:
`Jan 20 16:00:01 hostname local7 4 : 528: hostname: Jan 21 2020 12:00:01 AM.212 UTC :  %UC_CERT-4-CertValidLessThanMonth: %[Message=Certificate expiration Notification. Certificate name:VeriSign_Class_3_Secure_Server_CA_-_G3.der Unit:tomcat-trust Type:own-cert ][AppID=Cisco Certificate Monitor][ClusterID=][NodeID=hostname]: Alarm that indicates Certificate Expire in 30 days or lesser`
### Workaround/Solution
**Workarounds:**
**For Prime License Manager 10.5**
To delete the expired certificate (VeriSign_Class_3_Secure_Server_CA_-_G3) from the system, apply this COP file: ciscocm.plm-CSCvs64158_remove_sch_cert_C0050-1.k3.cop.sgn
**Note:** Please review the Readme file for installation instructions.
[PLM 10.5](https://software.cisco.com/download/home/286265616/type/282204704/release/COP-Files)
**For Prime License Manager 11.5**
To delete the expired certificate (VeriSign_Class_3_Secure_Server_CA_-_G3) from the system, apply this COP file: ciscocm.plm-CSCvs64158_remove_sch_cert_C0050-1.k3.cop.sgn
**Note:** Please review the Readme file for installation instructions.
[PLM 11.5](https://software.cisco.com/download/home/286308839/type/282204704/release/COP-Files)
**For Collaboration Products with version 11.0(1) and later**
Perform these steps to delete the expired certificate (VeriSign_Class_3_Secure_Server_CA_-_G3) from the system:
  1. Browse to the **Cisco Unified OS Administration GUI** (if it is a multi-node cluster, use the Publisher) and choose **Security > Certificate Management**.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img11580851548666.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img11580851548666.png "Related image, diagram or screenshot.")
  2. In the Certificate List, find the certificate where Common Name contains  _VeriSign_.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img21580851584184.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img21580851584184.png "Related image, diagram or screenshot.")
  3. Click **VeriSign_Class_3_Secure_Server_CA_-_G3**.
The Certificate Details window appears.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img31580851604905.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img31580851604905.png "Related image, diagram or screenshot.")
  4. In the Certificate Details window, click the **Delete** button.
A warning message appears.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img41580852494263.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img41580852494263.png "Related image, diagram or screenshot.")
  5. On the warning message, click **OK**.
The certificate is deleted from all nodes in the cluster.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img61580851672147.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img61580851672147.png "Related image, diagram or screenshot.")


**For all other versions**
Perform these steps to delete the expired certificate (VeriSign_Class_3_Secure_Server_CA_-_G3) from the system:
**Note:** Steps 1 through 3 are preparation steps that you must perform before you delete the certificate in step 4.
  1. Choose **Cisco Unified Serviceability > Tools > Control Center - Network Services**.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img71580851694461.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img71580851694461.png "Related image, diagram or screenshot.")
  2. Stop **Cisco Certificate Change Notification** on all nodes in the cluster.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img81580851711592.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img81580851711592.png "Related image, diagram or screenshot.")
  3. For IM and Presence Server(s): Stop the **Platform Administration Web Service** and **Cisco Intercluster Sync Agent**.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img91580851752429.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img91580851752429.png "Related image, diagram or screenshot.")
  4. Delete the certificate on all the nodes, including IM and Presence. Follow the instructions in the Workaround "_For Collaboration Products with version 11.0(1) and later_ " which appears elsewhere in this document.
  5. Start the services which were stopped in Step 2 and Step 3.


**Smart Call Home Certificate Renewal Procedure**
  * If Smart Call Home is disabled, no further action is required after the certificate has been deleted.
  * If Smart Call Home is enabled, follow these steps after the certificate has been deleted:


  1. Copy the certificate content from [UCM Administration Guide](https://www.cisco.com/c/en/us/td/docs/voice_ip_comm/cucm/admin/12_5_1SU1/adminGd/cucm_b_administration-guide-1251SU1/cucm_b_test-adminguide_chapter_010101.html) Section "_Information for Smart Call Home Certificates_."
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img101580851810639.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img101580851810639.png "Related image, diagram or screenshot.")
**Note:** The same certificate is valid for CUCM 10.5 and later versions.
  2. Upload the PEM file as tomcat-trust in Cisco Unified OS Administration GUI **Certificate Management** Page as shown in this screenshot:
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img111580851828670.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img111580851828670.png "Related image, diagram or screenshot.")
  3. Find the certificate where Common Name contains  _QuoVadis_ and verify that **QuoVadis_Root_CA_2** is listed as tomcat-trust.
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img121580852602378.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/705/fn70511img121580852602378.png "Related image, diagram or screenshot.")


**Solution:**
There is no solution available at this time.
