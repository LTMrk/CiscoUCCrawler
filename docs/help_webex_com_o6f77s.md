## July 22, 2026
## Webex WFO: WFM - Adherence Connector Enhancement for Granular Agent States
Webex WFO now introduced an enhanced WFM adherence connector to support the new Webex CC granular agent states feature. This update integrates with a new Webex webhook, enabling more precise tracking of multi-channel agent activity. Granular agent states are scheduled to roll out to all Webex CC customers on October 29, 2026.
**Get Ahead of the Change: Adopt the New Connector Now**
You can move to the new WFM adherence connector before the October 29 cutover, and we recommend doing so early. Adopting the connector now gives your team more time to reconfigure adherence state groupings, schedule the change during a maintenance window, and reduce the risk of Real-Time Adherence (RTA) reporting interruptions when granular agent states are enabled. 
  * Moving to the new connector requires re-grouping your adherence state configurations to align with the updated connector, but does **not** require enabling the granular agent states feature. 
  * Enabling granular agent states is optional until the October 29th rollout and can be turned on whenever you're ready. 
  * You can choose to re-group your states and enable granular agent states at the same time, or handle them as separate steps on your own timeline whichever works best for your organization. 


**Important Impact and Preparation**
Once granular agent states are enabled, either voluntarily before October 29 or automatically at the cutover, existing state grouping configurations will no longer align with the new multi-channel agent states. If your state groupings have not been reconfigured using the new adherence connector, RTA reporting will be interrupted until the reconfiguration is complete. 
We recommend reviewing the [**_Webex WFO Webhook Change Preparation Guide_**](https://help.webex.com/en-us/article/2t8a2h/Webex-WFO-Webhook-Change-Preparation-Guide) ahead of the release date for detailed planning steps and a walkthrough on reconfiguring your state groupings. If you require further assistance, please contact Cisco Support.

We have now introduced the Unified Call Summary Report in Analyzer, designed for organizations that use both Webex Contact Center and Webex Calling. ## Weighted Agent Insights routing
We’ve enhanced Webex Contact Center routing engine with Weighted Agent Insights routing, designed to improve how interactions are matched to agents.
This update uses Dynamic Skills, which represent agent-level attributes assigned directly to agents, to help the system make more relevant routing decisions. Supervisors can continue to use skill profile-based reskilling, while also benefiting from the ability to update Dynamic Skills directly on agents. By considering Dynamic Skills alongside other skills, contacts can be matched with agents whose attributes best fit the needs of the interaction.
What this means for your operations:
  * **Improved Matching** : Contacts can be routed to agents with the most relevant attributes for the interaction.
  * **Direct Agent Reskilling** : Update Dynamic Skills directly on agents, while continuing to use skill profile-based reskilling for existing skills.
  * **Greater Routing Flexibility** : Dynamic Skills help teams adapt routing behavior more quickly across queues and contact types.


These changes are intended to give teams more flexibility in managing queues and help ensure interactions are handled by the most suitable available agents.

## May 21, 2026
## Safe calling window for call recipients
Safe Calling Window is now available in Native campaign manager to help teams start outreach earlier without losing protection for recipient-local calling hours. It improves clarity around when contacts become callable and helps reduce idle time for agents at the beginning of the workday.
A new 'Safe calling window' configuration is now available in the 'Contact attempt strategy' node.
**Example use case:** Consider a debt collection campaign where agents work from '8:00 AM' to '5:00 PM' Central Time. A single contact has three phone numbers in 'Eastern', 'Mountain', and 'Pacific' time zones. 
  * Configure 'Campaign timings' as '8:00 AM' to '5:00 PM Central'. 
  * Configure 'Safe calling window' in Contact attempt strategy node as '6:00 AM' to '8:00 PM' in the contact’s local timezone.


At '8:00 AM Central', that contact is at '9:00 AM Eastern', '7:00 AM Mountain', and '6:00 AM Pacific'.
Since all three numbers are already within the configured safe calling window, the contact can be sent to the dialer right at the start of the agent’s shift. This means agents can begin working on available contacts sooner instead of waiting for the latest timezone on the record to reach a safer default threshold.

## Native Webex Campaign Management: Infer a contact’s timezone from their US Postal Service ZIP code
This feature is only applicable to clients in the USA.
Until now, the timezone for a US-based call recipient was derived from that contact’s phone area code(s) to ensure the outbound call is made within a ‘Safe Calling Window’ within the overall campaign schedule. However, as customers move from one city/town to another, they are very likely to keep their mobile phone number – thus the timezone inferred from the phone area code can be incorrect.
With the introduction of this feature in ‘Field Mapping step #5’, you will now have the option to _“Derive timezone from contact list: Based on US ZIP codes”_. We have mapped each of the approximately 42,000 ZIP codes in the USA to a timezone. So if you select this new option while configuring ‘Field Mapping step#5’, then the system will infer the timezone for each contact from their ZIP code, instead of inferring the timezone from their phone area code.
This feature may help you to improve your outbound campaign efficiency and improve your compliance with ‘calling window’ regulations.

We are excited to expand our AI Quality Management suite to include comprehensive support for AI agents, bringing the same capabilities previously reserved for human-agent interactions. This upcoming release enables supervisors to assign evaluation forms to AI Agents along with existing Queues, Teams and Human Agents, enabling AI based automated evaluations for AI agent interactions. Supervisor will have the capability to override AI generated evaluation score manually. Speech analytics metrics such as Dead air time and Word ratios will also be available to better understand AI agent interactions. Supervisors will be able to view all completed interactions in the same grid with a filter for AI agent / Human agent interactions. A new AI Agent Performance Dashboard will provide a unified view of AI agents performance across quality and operational metrics to supervisors.
A Webex AI Quality Management SKU is required to enable these capabilities.
### Webex AI Quality Management: Customer sentiment for AI agent interactions
Supervisors will be able to view customer sentiment for completed AI agent interactions in Supervisor Desktop. The existing Customer sentiment column in the completed interactions grid will display the overall sentiment as Positive, Negative, or Neutral, together with a sentiment score from -100 to +100. Supervisors will be able to filter interactions by customer sentiment and agent type, such as human agent or AI agent.
A Webex AI Quality Management SKU is required to enable these capabilities.
### Webex AI Quality Management: View team leaderboard in Agent Central
Supervisors will be able to view a team leaderboard in Agent Central. The leaderboard will list agents in the team and rank their performance across metrics such as overall score, handle time, wrap-up time, and evaluation score.
A Webex AI Quality Management SKU is required to enable these capabilities.
## **Supervisor desktop**
  * The Team Performance Details page operates at optimum performance for up to 500 agents. A supervisor with access to more than 500 agents might not experience the best performance with the Team Performance Details page. 
  * When agent 2 is conferencing into a call that is being handled by agent 1, agent 2’s details does not show all the call metadata. Also, when agent 2 is consulting with agent 1, the call details are not available on agent 2’s active interaction details modal. These issues will be fixed in a future release as an enhancement. 
  * The default layout Cisco provides to the Global Layout section doesn’t support cross launching the Webex app. As an alternative, you can customize any of the layouts to add the cross-launch option.
  * When conferencing with a dial number mapped to an entry point wherein 2 agents - agent1 and agent2 are conferencing, the second agent’s contact status displays “Connected” instead of “Conferencing” in the Team Performance Details page. Note that consulting and conferencing a dial number mapped to an entry point is still in limited availability. 
  * There are differences in data between Supervisor Desktop reports and Homepage. For more information, see [Comparison of KPI Cards in Supervisor Desktop and Analyzer](https://help.webex.com/en-us/article/nqpc4zf/Comparison-of-KPI-Cards-in-Supervisor-Desktop-and-Analyzer).
  * Supervisors must have unique number assignments. Supervisor1 signs into the Supervisor Desktop with a number. Supervisor1 needs to sign out and sign in with a different number, so that Supervisor2 can sign into Supervisor Desktop with the same number used by Supervisor1. If you use the same phone number for different supervisors, contact your account team, partner, or Cisco support for assistance.
  * To save the Inactivity Timeout setting on Control Hub, you must enter a value for the Auto Wrapup interval setting. However, this isn't applicable when you use the Management Portal for tenant level settings.


## **Courtesy callback routing to capacity-based teams is not supported**
Courtesy callback isn't supported with capacity-based teams (CBT). CBTs have no individual agents assigned to them, and courtesy callback requires an Agent ID to function. Therefore, if courtesy callback flows to an entry point or a queue served by a CBT, the call fails.
