Não foi possível registrar um dispositivo Webex Room ou Webex Call IP no Webex
![list-menu](https://help.webex.com/images/feedback.svg)Comentários?
Se um cliente não conseguir registrar seu endpoint Webex ou telefone no Webex, isso é mais freqüentemente devido a um problema de rede. Uma causa comum disso é o uso de um roteador Meraki ou aparelho de segurança nas configurações padrão. 
## Não foi possível registrar um dispositivo Webex Room ou Webex Call IP cisco.
## Não consigo registrar meu telefone com Webex Call.
## Não consigo registrar um dispositivo Webex Room celular.
Ao tentar registrar um telefone, TelePresence ou Cisco Webex dispositivos ATA para Webex, um cliente pode receber erros como o seguinte: 
  * "Não é possível conectar-se ao serviço Webex"
  * Avisos de que um [servidor NTP (Network Time Protocol)](https://en.wikipedia.org/wiki/Network_Time_Protocol) está inacessível
  * sua hora pode ser definida para um dia a partir de novembro de 2015
  * um erro de certificado
  * erro de segurança
  * o dispositivo pode estar travado em "Registrando"

Possíveis causas: 
  * O cliente está usando um dispositivo ou roteador de segurança Meraki na sua rede. 
    * Isso é geralmente causado pelos roteadores Meraki ou dispositivos de dispositivos de segurança, que ao funcionar como um servidor DHCP, anunciarão seu próprio endereço de IP como o servidor NTP da rede na opção DHCP 42. Infelizmente, esses dispositivos não hospedam realmente um servidor NTP acessível à rede, portanto, dispositivos como os telefones cisco 7800 e 8800 series tentarão conectar ao dispositivo Meraki para atualizar seu horário, mas a conexão irá falhar uma vez que nenhum servidor NTP está acessível.
  * O dispositivo é incapaz de alcançar um servidor NTP e definir sua hora para a hora e data corretas. 
    * **Isso geralmente ocorre devido a um dos dois motivos** : 
      * NTP (porta UDP 123 do dispositivo para a Internet) está sendo bloqueado pela rede, firewall ou roteador.
      * O servidor DHCP da rede está transmitindo um servidor NTP inutilizável [na opção 42](https://en.wikipedia.org/wiki/Dynamic_Host_Configuration_Protocol#DHCP_options).

**Solução** :  
  
**Se o cliente tiver segurança Meraki em sua rede:**  
  
Uma solução alternativa é reconfigurar o dispositivo Meraki para anunciar um endereço IP de servidor NTP válido. Recomendamos que um cliente primeiro execute o _**comando nslookup 0.tandberg.pool.ntp.org e copie o primeiro endereço IP que é retornado** _ pelo servidor DNS. Depois disso, eles podem seguir as instruções documentadas de Meraki para definir um valor de opção DHCP personalizado para a opção 42 e, em seguida, reiniciar o telefone ou o [](https://documentation.meraki.com/General_Administration/Cross-Platform_Content/Setting_Custom_DHCP_Options) endpoint. Depois que o dispositivo é inicializado, ele deve consultar o servidor DHCP para um endereço IP, receber o novo endereço IP do servidor NTP e conectar-se a ele, atualizar sua hora e, em seguida, um deve ser capaz de continuar a sequência de ativação regular.  
  
**Se o NTP (porta UDP 123) estiver bloqueado**  
  
Isso precisará ser resolvido pelas equipes de rede, firewall ou segurança e administração do cliente.  
  
Uma solução alternativa para isso é atualizar manualmente o firmware do dispositivo para a versão mais recente compatível com o Webex. Isso pode ser feito seguindo [as instruções do upgrade.cisco.com](http://upgrade.cisco.com). Note que, a partir de 15 de outubro de 2016, o upgrade.cisco.com é compatível apenas com dispositivos das séries 7800, 8800 e das séries DX.
