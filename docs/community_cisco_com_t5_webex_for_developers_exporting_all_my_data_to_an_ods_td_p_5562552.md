Hi Florian,
I would use a hybrid approach:
  * GraphQL Search API for interaction and agent history. Query small time windows, paginate the results, and upsert them into your warehouse. Avoid reloading the full history each time.
  * Webhooks for near-real-time events, followed by periodic GraphQL reconciliation.
  * Admin Audit Events API for configuration changes.


The default limit is 300 requests per minute and 30 requests per second per client ID. Your application should also respect the `Retry-After` header if it receives a `429`.
Relevant documentation:
  * [Search API](https://developer.webex.com/webex-contact-center/docs/getting-started-with-search-api)
  * [Webhooks](https://developer.webex.com/webex-contact-center/docs/using-webhooks)
  * [Rate limits](https://developer.webex.com/webex-contact-center/docs/rate-limiting)
  * [Admin Audit Events](https://developer.webex.com/admin/docs/api/v1/admin-audit-events)
