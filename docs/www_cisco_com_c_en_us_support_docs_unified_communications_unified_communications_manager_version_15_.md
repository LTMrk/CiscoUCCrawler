## Scenario 1: Phones Not Register after Call Manager, TVS and ITL Certificate Renewal
[![note-icon](https://www.cisco.com/c/dam/en/us/td/i/templates/note.gif)](https://www.cisco.com/c/dam/en/us/td/i/templates/note.gif "note-icon")
**Note** : This scenario apply to deployments under CUCM mixed-mode and non-secure clusters, in addition, applies to the self-signed certificates and CA certificates.
When Call Manager , TVS and ITL certificates expired and they were renewed at the same time, It causes to have all our phones in an unregistered state thta causes a major Impact on the system, this is an expected behaviours as we trigger the phones to not trust in the CUCM. 
### **Verification**
1. Ensure the certificates are already expired under**Cisco Unified OS Administration >****Security > Certificate Management **
[![jozarago_2-1771791248259](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-01.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-01.png "jozarago_2-1771791248259")
2. Search by Callmanager, TVS or ITL under the filter at the top of the page and use the contains or begins with options: 
[![jozarago_3-1771791388891](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-02.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-02.png "jozarago_3-1771791388891")
3. The certificates must see up to date and vefiry under the **Expiration** column (same for TVS and ITL certificates) 
[![jozarago_4-1771791536793](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-03.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-03.png "jozarago_4-1771791536793")
4. Once verified everything is good after the certificate renewal, the phones are shown as **Unregistered** state.
[![jozarago_5-1771791972470](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-04.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-04.png "jozarago_5-1771791972470")
### Solution
There is 2 options to fix the issue: 
  1. Perform a factory reset of the phone that allows the phone erase the currently security settings and allow the phone to grab the new certificates
  2. Update the ITL and CTL certificates from CLI on the publisher node an use the command ****utils itl reset localkey.  
This step affects all phones including registered phones, make sure to perform this after hours.****

## Scenario 2: Single sign-on does not work after Tomcat certificate renewal
[![note-icon](https://www.cisco.com/c/dam/en/us/td/i/templates/note.gif)](https://www.cisco.com/c/dam/en/us/td/i/templates/note.gif "note-icon")
**Note** : This scenario can apply to deployments that uses cluster-wide or per-node agreement for single sign-on configuration
Login within CUCM with Single Sign-on (SSO) it displays an error message ¨Error while processing saml response¨ or ¨Error while processing saml response Failed to decrypt the secret key¨
### Verification
  1. Ensure all nodes contains a valid tomcat certificate if self-signed or contains the new multi-san tomcat certificate associated.
  2. Use **set samltrace level debug** in all CUCM nodes via CLI in order to activate SSO logs on debug level
  3. Recreate the issue by login again to CUCM and use SSO method.
  4. Collect Tomcat SSO logs after the incident, and verify you get this message:

### Solution
Export of CUCM metadata after Tomcat certificate renewal and import to the Idendity Provider Server to ensure they have the new tomcat certificate for this communication.

**Caution** : Techinical Assistance Center (TAC) recommends the next steps in order to prevent any issue after the renew of Tomcat certificate, recommend to perform this procedure after hours.

  * Access to **CM administration > System > SAML **Single Sign-on****


****  
****[![Captura de pantalla 2026-03-04 a la\(s\) 2.29.03 p.m.](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-08.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-08.png "Captura de pantalla 2026-03-04 a la\(s\) 2.29.03 p.m.")
  * Select **Disable SAML SSO**

  * This process needs to be performed in all the rest of the nodes via GUI if per-node agreement is used.


2. Renew Tomcat certificate in CUCM cluster
[![Captura de pantalla 2026-03-04 a la\(s\) 2.05.55 p.m.](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-10.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-10.png "Captura de pantalla 2026-03-04 a la\(s\) 2.05.55 p.m.")
Overall procedure to renew Tomcat multi-san certificate in CUCM cluster:
  * Navigate to **OS administration > Security > Certificate management**.
  * Select **Generate CSR**


  
[![Captura de pantalla 2026-03-04 a la\(s\) 2.56.50 p.m.](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-11.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-11.png "Captura de pantalla 2026-03-04 a la\(s\) 2.56.50 p.m.")
  * Select **Tomcat** in Certificate Porpuse.
  * Select **Multi-SAN** in Distribution.
  * Ensure all nodes in the cluster are listed under **Auto-populated Domains**.


  
[![Captura de pantalla 2026-03-04 a la\(s\) 2.57.55 p.m.](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-12.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-12.png "Captura de pantalla 2026-03-04 a la\(s\) 2.57.55 p.m.")
  * Select **Generate**. Ensure CSR is created in all the nodes in the cluster.
  * Download the generated CSR from CUCM publisher and sign it with a Certificate Authority (CA) server.
  * Go to **OS administration > Security > Certificate management**. Select **Upload certificate/Certificate chain.**
  * Upload CA certificates as Tomcat-trust.
  * Repeat step 6 and now upload the Tomcat signed certificate as Tomcat.
  * Once completed and verified all nodes have the new tomcat certificate applied, restart Tomcat service through CLI in all the nodes in the cluster with this command **utils service restart Cisco Tomcat.**


For more information refer to the this documentation:
  * [Regenerate Tomcat self-signed certificate](https://www.cisco.com/c/en/us/support/docs/unified-communications/unified-communications-manager-callmanager/214231-certificate-regeneration-process-for-cis.html#toc-hId--24706933)

For more information, refer to [Configure SAML SSO on Identity Provider](https://www.cisco.com/c/en/us/td/docs/voice_ip_comm/cucm/SAML_SSO_deployment_guide/15/cucm_b_saml-sso-deployment-guide-release-15/cucm_m_saml-sso-configuration-1251.html#task_6BFEE8DE6F8758477DF7DAD3E43A07D6)

  * If cluster-wide, this step is available to check multi-san certificate in all the nodes, select **Test for multi-server tomcat certificate**. once completed, select **Next.**


  
[![marcoalh_96-1732756443753](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-18.png)](https://www.cisco.com/c/dam/en/us/support/docs/unified-communications/unified-communications-manager-version-15/225746-troubleshoot-common-issues-with-18.png "marcoalh_96-1732756443753")

4. Restart required services after SSO enabled.
