### Problem Description
The affected products (listed in the Products Affected section) might not respond under certain conditions.
### Background
Some Seagate hard drives might not respond to all requests. This can occur when the drive asserts too frequently in a short period of time, which leads to an assert storm.  
  
**Note:** If you run Firmware (FW) Version 0004 or later on the 146GB and/or the 300GB hard drives, or firmware Version 0002 or later on the 500GB, 1TB, or 2TB hard drives, then this issue should not occur.  
  
If you run a FW version that is earlier than that previously described, and you believe that you have encountered this issue, complete these steps:
  1. Search for messages in the SEL logs and/or the OBFL logs. You might receive one or more messages to indicate that the RAID, RAID controller, Physical Drive (PD), or the Virtual Drive (VD) appears degraded or has failed.  
  
Here are some examples of messages that you might encounter with the Cisco UCS C-Series servers:   

```
**BMC:storage:-: SLOT-5: Error on PD 17(e0x18/s16) (Error 02) 

BMC:storage:-: SLOT-5: State change on PD 17(e0x18/s16) from ONLINE(18) to FAILED(11) 

BMC:storage:-: SLOT-5: State change on VD 01/1 from OPTIMAL(3) to DEGRADED(2) 

BMC:storage:-: SLOT-5: VD 01/1 is now DEGRADED**
```
  
Here is an example of a Drive Fault Assert message:  

```
**HDD_07_STATUS: Drive Slot sensor, Drive Fault was asserted**
```
  
Here is an example of a Predictive Failure Alert message that you might encounter with the Cisco UCS B-Series servers:  

```
**CIMC | Drive slot(Bay) SAS1_FAULT #0x22 | Predictive Failure asserted | Asserted**
```

  2. If you see any of the previously described messages, then it is possible that your system has encountered this issue. In order to verify that this is the problem, you must power cycle the hard drive(s) to clear/stop the assert storm. In most cases, this involves a power cycle of the server. If the system comes online normally and begins to work properly, then the issue described in this document is the problem.   

  3. If a power cycle of the server does not resolve the issue, open a case with the Cisco Technical Assistance Center (TAC) so that they can help you troubleshoot the issue.


### Problem Symptom
The affected hard drives do not respond to all requests.
### Workaround/Solution
The affected hard drives are not defective, but they do require a FW update. The HDD can be power cycled in order to correct the problem. However, this is not expected to resolve the problem permanently; it is only a short term fix.   
  
In order to permanently fix this problem, you must upgrade the HDD FW:
  * Seagate 146/300GB HDDs must be upgraded from FW Version 0002 to FW Version 0004.  

  * Seagate 500GB/1/2TB HDDs must be upgraded from FW Version 0001 to FW Version 0002.


**Note:** Refer to the **Updating the Firmware on Cisco UCS C-series Servers** section of the [Cisco Host Upgrade Utility 1.5(1) User Guide](http://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/c/sw/lomug/1-5-x/b_huu_1_5.html) for more information about HDD FW upgrades.   
  
Both the B- and C-Series servers use the same Host Update Utility (HUU) in order to perform an HDD upgrade. Though the HUU is traditionally intended for use with C-Series servers, the B-Series servers are still able to update disks with this utility. Both the M2 and the M3 servers use the Version 1.5.3.x HUU in order to upgrade the FW.   
  
Use this information, dependent upon your server model:
  * If you run a UCS C-Series server that supports Version 1.5.x HUU, then use the instructions that are provided in the [Updating the Firmware on Cisco UCS C-Series Servers](http://www.cisco.com/en/US/docs/unified_computing/ucs/c/sw/lomug/1.5.x/b_huu_1_5_3_chapter_011.html) section in order to upgrade your hard drive(s) FW.  

  * If you run a UCS B-Series M1 server (not compatible with HUU), then open a support case with the Cisco TAC.  

  * If you run a UCS C-Series server that does not support an upgrade to Version 1.5.x HUU, then use the information that is described in the **How to Identify Affected Products** section of this document in order to upgrade your hard drive(s) FW.


### How To Identify Affected Products
**Important:** Ensure that you back up any data, as there is always a possibility (though unlikely) for data loss during a FW upgrade. 
**Note:** Do not use the Cisco Product ID number in order to identify the drive; use only the specific Seagate HDD model numbers that are affected. The Seagate HDD model number is located in the **Comments** column of the table that is provided in the **Products Affected** section of this document.   
  
This HDD FW upgrade procedure was designed in order to upgrade the Seagate 146/300/500GB and 1TB/2TB HDDs. Complete these steps in order to perform the HDD FW upgrade:
  1. Verify the model number and FW version of your Seagate HDD(s).  
  
**Note:** You can also check the FW version via the CIMC CLI. Refer the **Optional FW Verification** section for more information.  
  
For C-Series servers, log in to the CIMC and confirm your model number and FW version via the Inventory page (Product ID):  
  
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n48ro41547150919554.jpg)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n48ro41547150919554.jpg "Related image, diagram or screenshot.")  
  
For B-Series servers, log in to the Managed Objects Browser of your UCSM VIP and perform a query for the **storageLocalDisk** class. In order to complete this, replace your UCSM IP address with the **https://IP/visore.html?f=class &q=storageLocalDisk** link format:  
  
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n68xd21547150933969.png)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n68xd21547150933969.png "Related image, diagram or screenshot.")  

  2. Download the HUU Version 1.5(3)2 or later for C240 M3 servers and for UCS servers that do not support Version 1.5(3)2. HUU ISO images can be downloaded at [UCS C240 M3 Rack Server Software-Unified Computing System (UCS) Server Firmware](https://software.cisco.com/download/release.html?mdfid=284296254&flowid=&softwareid=283850974)
  3. Open the KVM console within CIMC or the UCS Manager.  

  4. Map the HUU ISO file that you downloaded in Step 2 from the VM tab within the KVM console.  

  5. Restart the UCS Server. Optionally, hit F6 during the boot in order to manually select the device from which you want to boot. In order to boot from the HUU ISO, select **Cisco Virtual DVD/CD**.  

  6. After the HUU boots, it displays the HDD Firmware Upgrade screen. After a few minutes, it displays the HDDs in your system that can be upgraded.  
  
**Important:** If you run FW Version 0004 or later on the 146GB and/or the 300GB hard drives, or FW Version 0002 or later on the 500GB/1TB/2TB hard drives, then no additional steps are required.  
  
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n48snd1547150950250.jpg)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n48snd1547150950250.jpg "Related image, diagram or screenshot.")  

  7. For 500GB, 1TB, and 2TB hard drives, verify that the current FW version is 0001 and that the new FW version is 0002 or later. If this is correct, skip to Step 9. If you do not have a 500GB, 1TB, or 2TB HDD, then proceed to Step 8.   

  8. For 146GB and 300GB drives, verify that the current FW version is 0002 and that the new FW version is 0004 or later.  

  9. Select **Upgrade All** in order to upgrade all of the HDDs from the current version to the new version. Wait for the upgrade to finish. Once the upgrade is complete, the Status should display **Pass**. This can take several minutes and it might appear as if your system is frozen; however, do not perform any further actions until it is complete.  

  10. Reboot the server when the update is complete. Log into the HDD Firmware Update utility and confirm that the **Current Version** matches the **New Version**.   

  11. The update is now complete. Dismount the HUU ISO image from the KVM and boot the server to the Operating System (OS). Once the system is fully booted, you must log out of CIMC/UCS Manager and log back in so that you can view the changes.  
  
[![](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n48t0i1547150965477.jpg)](https://www.cisco.com/c/dam/en/us/support/docs/field-notices/638/fn63812_n48t0i1547150965477.jpg "Related image, diagram or screenshot.")
